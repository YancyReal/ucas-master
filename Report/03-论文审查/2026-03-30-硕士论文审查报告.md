# 2026-03-30 硕士论文审查报告

审查对象：硕士学位论文主稿及其章节组织  
审查范围：当前问题诊断、后续任务拆解、分批修改计划  
审查结论：建议进行结构性重构，并按分批方式推进正文改写

## 一、总评

当前论文并不缺少工作量，也不缺少技术材料。现阶段的主要问题不在于“没有内容”，而在于“材料的组织方式不符合学术论文的论证重心”。现稿对实现过程、实验链路、失败方案和补充说明的展开过多，导致正文阅读体验更接近技术报告或工程归档，而不是围绕研究问题、技术方案、实验结果和结论展开的学术论文。

从整体判断看，论文现有六章框架仍可保留，但第4章和第5章的职责边界需要明显调整；摘要、绪论和结论也需要同步收束表述，避免从开头到结尾都带有过强的防御性说明。

## 二、当前主要问题

### 1. 章节职责失衡，论文主线不够集中

- 第4章当前更像“实验平台与验证手册”，而不是“实验设计与验证结果”。
- 第5章当前更像“优化过程归档”，而不是“围绕三项正式方案展开的研究论证”。
- 正文主线没有稳定收束到“研究背景、关键问题、技术方案、实验设计、数据结果、结论”这一典型论文路径上。

### 2. 过程性内容偏多，结论性内容不够突出

- 编译流程、部署流程、测试链路、日志组织方式等操作性内容占比偏高。
- 失败方案、补充消融、叠加负例、方法归纳等内容写得过满，压缩了三项正式方案的主体地位。
- 读者容易先看到“作者如何解释边界”，而不是先看到“本文最终得到了什么结论”。

### 3. 防御性表达过强，影响学术表述的直接性

- 摘要、绪论、结论均提前引入大量“证据层级”“收益边界”“阶段性结论”“失败样本”等表述。
- 这类内容本身并非不能保留，但当前出现位置过早、重复次数过多，削弱了论文主结论的清晰度。

### 4. 用词与文风存在明显收束空间

- 存在较多模板化、说明书化、生成式痕迹较强的句式。
- “副作用”这类表达不够专业，应根据上下文替换为“开销”“额外代价”“性能回退”“代码体积增加”等更准确的术语。
- “口径”“闭环”“可复核”“低扰动”“门控”“收益边界”等术语出现过密，导致文风偏硬，阅读阻力较大。
- 部分句子长度过长，同一句中承载了现象、解释、限定和结论，影响可读性。

### 5. 图示体系不足，机制说明不够直观

- 当前结果图多于机制图，数据图多于结构图。
- 绪论、相关技术、第4章、结论等部分缺少必要的结构图或流程图支撑。
- 三项正式方案缺少统一风格的机制图、流程图或伪代码示意，读者理解成本较高。

### 6. 论文性不足的根本原因

综合来看，现稿的核心问题可以概括为一句话：**材料很多，但论证顺序失衡；过程写得太满，结论写得不够突出。**

## 四、分批修改计划

## 1. 总体策略

本轮修改采用以下策略：

- 采用**激进重构**，但保留六章总框架。
- 对失败方案和补充消融采用“**正文压缩，附录保留**”的处理方式。
- 按“**先改结构，再补图**”的顺序推进，降低返工风险。

## 2. 新的正文组织目标

全文的叙事目标统一为：

**研究背景与问题提出 -> 技术基础与困难分析 -> 适配设计与实现 -> 实验设计与正确性验证 -> 性能优化与结果分析 -> 总结与展望**

在此目标下：

- 第3章负责回答“做了什么适配工作”。
- 第4章负责回答“如何证明适配与实验结论可信”。
- 第5章负责回答“哪几项优化方案有效、效果如何、适用范围是什么”。

## 3. 第4章重构原则

- 删除独立展开的编译流程、部署流程和工具使用说明式段落。
- 将验证链路从“操作步骤说明”改写为“实验设计与验证方法说明”。
- 将正确性验证结果与性能评测设计明确区分。
- 使第4章的核心问题从“作者如何测试”转变为“实验如何支撑论文结论”。

## 4. 第5章重构原则

- 仅保留三项正式方案作为正文主线。
- 失败方案保留简短对照价值说明，不再保留大篇幅展开。
- 减少“方法论总结”式抽象表述，优先保留数据、现象与解释。
- 把“正式方案为何值得保留”作为第5章最后的落点，而不是把“为什么很多方案失败”作为主要阅读体验。

## 5. 文风与术语统一原则

- 将“副作用”按语境替换为更专业表达：
  - 开销
  - 额外代价
  - 性能回退
  - 代码体积增加
  - 缓存扰动
- 统一以下术语：
  - benchmark -> 基准测试
  - workload -> 工作负载
  - baseline -> 基线
  - SciMark 的大小写写法
  - debug 构建、宿主机测试、目标机回归等关键表述
- 系统削减以下高频模板句：
  - “需要说明的是”
  - “这说明”
  - “可以得到”
  - “基于这一观察”
- 每句话尽量只承载一个判断，优先采用“现象 -> 解释 -> 结论”的短句组织方式。

## 五、风险点与验证建议

### 1. 主要风险

- 第5章压缩失败方案后，正文可能出现“结论过于单薄”的风险。
- 第4章删减流程性内容后，可能出现“实验复现信息不够”的风险。
- 大范围调整段落后，可能出现交叉引用、图表引用和附录引用断裂的问题。
- 文风统一过程中，若只做表面替换，可能损伤原有技术表达的准确性。

### 2. 验证建议

- 每一批改完后都执行一次完整编译：
  - `cd /workspace/ucasthesis && ./artratex.sh xa Thesis.tex`
- 每一批都检查以下内容：
  - 目录是否反映章节新定位
  - 图表与附录引用是否正确
  - 摘要、绪论、结论的方案表述是否一致
  - 是否仍保留明显的“技术报告式”长段落
- 在最终收尾时单独做一轮语言清理，重点检查术语统一、长句拆分和模板化句式削减情况。

## 六、结论

当前论文的核心矛盾已经明确：问题不在于没有技术内容，而在于现有内容的组织方式不足以支撑一篇论证紧凑、主线清晰的硕士学位论文。后续修改不应继续增加材料，而应重点完成以下三项工作：

1. 重构章节职责，尤其是第4章与第5章  
2. 压缩过程性内容，突出正式方案与主要结论  
3. 统一术语和文风，并补足机制图与流程图

按上述分批计划推进后，论文有望从“工程内容充分但论文性偏弱”的状态，转入“结构清晰、论证收束、结论明确”的送审准备状态。
