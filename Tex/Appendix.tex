\chapter{补充实验与归档结果}

正文第 5 章只保留共享正式基线、共享正式重复测量数据的主结论。本附录收录三类补充材料：一是与正文主线正交的启动期实验，二是用于说明候选方向边界的补充消融，三是候选方案的筛选结果。这些材料对理解研究过程有价值，但不直接参与正文的主结论比较。

\section{DexFileVerifier 阶段链实验}\label{app:dex-phase-chain}

除正文中的三项正式方案外，本文还围绕 \texttt{libdexfile/DexFileVerifier} 的启动期热点进行过一组独立阶段链实验，用于观察 DEX 校验路径上的局部优化是否能够形成可复现收益。该组实验采用独立基线，与正文第 5 章使用的正式基线和三项正式方案完全隔离，因此不并入主结论，只作为补充材料保留。

之所以保留这组实验，是因为 DexFileVerifier 并不是与正文主线无关的偶发热点。ART 直接执行 DEX 格式，并在安装期执行严格的字节码验证；同时，合法 \texttt{.dex} 文件还要求字符串数据满足有效的 \texttt{MUTF-8} 编码，并在多类元数据结构中大量使用 \texttt{uleb128/sleb128} 变长编码\citep{AndroidRuntime2024,VerifyingAppsArt2023,DexConstraints2025,DexFormat2025}。因此，DexFileVerifier 路径上的文件完整性检查、字符串解码和变长整数解析，本身就是启动期与加载期中的真实成本链。

该阶段链依次包含四组累计改动：第一阶段引入文件边界缓存、热点 helper 内联和容器预留容量；第二阶段将 \texttt{offset\_to\_type\_map\_} 的访问方式调整为更紧凑的 \texttt{vector + lower\_bound}；第三阶段加入 UTF-8 查表和 ASCII fast path；第四阶段补充 LEB128 fast path。图~\ref{fig:dexfileverifier-phase-chain} 给出了这四个阶段在 \texttt{startup.helloworld} 和 \texttt{scimark.lu.small} 上的归一化结果。

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.92\textwidth]{mybenchmark/dexfileverifier-phase-chain-speedup}
    \caption{DexFileVerifier 阶段链实验的归一化收益}
    \label{fig:dexfileverifier-phase-chain}
\end{figure}

结果表明，\texttt{startup.helloworld} 是这条阶段链的主要受益对象。第二阶段起开始出现明确正收益，到 \texttt{phase1234} 时累计收益约为 \texttt{+5.46\%}；而 \texttt{scimark.lu.small} 没有形成稳定提升，说明该方向更适合启动期和加载期路径，而不是数值内核的稳态执行。正文不保留这组结果，正是因为它回答的是“启动期局部路径能否进一步压缩”，而不是“三项正式方案谁更值得作为主结论”。

\section{Intrinsic 机制的补充验证}\label{app:intrinsic-ablation}

正文第 5 章讨论的是三项正式方案，但 LoongArch64 Intrinsic 机制本身仍然值得单独说明。为量化该机制对基准测试的真实贡献，本文额外设计了一组“关闭 / 开启 Intrinsic”的补充实验，比较两种状态在 \texttt{JIT} 与 \texttt{interpreter} 两种执行模式下的差异。该实验的目的，是回答 Intrinsic 支持是否已经形成可量化收益，而不是把它与正文三项正式方案并列为同一层级的论文主线。

该补充实验比较的对象分别为“关闭 LoongArch64 invoke Intrinsic dispatch”的基线版本与“恢复 Intrinsic 支持”的对照版本。测试集合覆盖 21 个 \texttt{SPECjvm2008} 工作负载，以及 \texttt{DaCapo} 的 \texttt{avrora}、\texttt{pmd} 和 \texttt{h2}；其中 \texttt{h2} 仅在 \texttt{JIT} 模式可用。对 \texttt{SPECjvm2008}，本文采用 \texttt{enabled\_ops / disabled\_ops} 计算 speedup；对 \texttt{DaCapo}，采用 \texttt{disabled\_time / enabled\_time} 计算 speedup，因此表中数值越大表示开启 Intrinsic 后越有利。

从逐工作负载结果看，\texttt{crypto.aes}、\texttt{startup.crypto.aes}、\texttt{h2} 和 \texttt{crypto.signverify} 是最具代表性的收益点，说明 Intrinsic 更适合命中标准库和内建语义路径。相对地，\texttt{pmd} 仍出现明显回退，这也说明 Intrinsic 并不是对所有 Java 工作负载都普遍有效。正文不将该实验并入主线，正是因为它回答的是“LoongArch64 Intrinsic 机制总体是否有价值”，而不是“三项正式方案中哪一项最值得保留”。

\section{完整 SIMD 覆盖候选版消融}\label{app:full-simd-ablation}

在完成正文方案三之后，本文又围绕 LoongArch64 SIMD 能力补齐做了一轮后续候选实验，比较三种状态：\texttt{S0} 为无 SIMD 对照基线，\texttt{S1} 为正文采用的最小可用 SIMD 版本，\texttt{S2} 为后续整理出的完整 SIMD 覆盖候选版。该实验使用 \texttt{2026-03-18} 独立采集的数据集，目的不是替换正文方案三的正式结论，而是回答“能力覆盖继续扩大后，整体收益是否还能稳定上升”。

本轮消融覆盖当前设备上可稳定运行的 21 个 \texttt{SPECjvm2008} 工作负载，以及 \texttt{DaCapo} 的 \texttt{avrora}、\texttt{pmd} 和 \texttt{h2}。所有工作负载默认重复 3 轮，\texttt{lu.small}、\texttt{sor.small}、\texttt{fft.small}、\texttt{mpegaudio}、\texttt{h2} 和 \texttt{pmd} 在 \texttt{JIT} 模式下扩展到 5 轮。由于该实验不与正文第 5 章共享同一正式基线链，因此这里只讨论 \texttt{S0/S1/S2} 之间的相对关系，不与正文中的绝对收益数值直接混写。

表~\ref{tab:scheme3-full-ablation} 表明，如果评价标准是“全部 \texttt{JIT} 工作负载的几何平均”，正文采用的最小版本 \texttt{S1} 仍然更稳妥，因为 \texttt{S1 / S0 = 1.0318x}，而 \texttt{S2 / S0 = 1.0252x}，\texttt{S2 / S1} 仅为 \texttt{0.9936x}。继续扩大 SIMD 覆盖并不会自动带来整体均值上升，部分 startup 或非关键工作负载上的小幅拖累已经足以抵消一部分新增收益。

但图~\ref{fig:scheme3-full-ablation-key} 也表明，\texttt{S2} 并非简单退化版本。相对 \texttt{S1}，\texttt{S2} 在关键工作负载上的几何平均仍有 \texttt{1.0157x} 的增益，并在 \texttt{scimark.lu.small}、\texttt{h2} 和 \texttt{avrora} 上继续取得局部提升。因此，更合适的结论是：\texttt{S1} 仍应保留为正文方案三的正式版本，而 \texttt{S2} 则应视为“完整覆盖候选增强版”，留待后续继续验证。

\section{候选对比方案与筛选结果}\label{app:candidate-schemes}

正文第 5 章只保留三项正式方案，但实际筛选过程中还比较过多组同类候选方向。保留这些材料的目的，不是放大未保留方向，而是说明本文并非只展示成功样本，而是在同一研究问题下比较过多种可行思路，并最终筛出最适合写入正文的版本。需要说明的是，本节数据沿用筛选阶段的固定对照链，与正文正式基线并不相同，因此只作为“方案选择过程”的补充证据，不参与正文主结论比较。

这一类候选样本的共同点是：目标热点在 flamegraph 中确实可见，但占比不够高，或者工作负载类型与方案原理并不匹配，因此局部路径变快并没有带来端到端提升。也正因为如此，正文最终保留的是“运行时字符串热路径批量化”这类能够稳定对应到 \texttt{pmd} 字符串热点的方向，而不是把所有运行时搬运相关改动都并入主线。

综合图~\ref{fig:candidate-schemes-screening-map} 与本节两张候选方案对比表，可以得到更清楚的筛选结论：真正值得进入正文的方案，必须同时满足三点，即命中正式工作负载的主路径、能够通过目标机回归形成语义约束、并且在统一实验设置下给出可解释的端到端收益。未被保留的候选方向并非“完全没有命中点”，而是其收益不足以支撑论文主结论。
