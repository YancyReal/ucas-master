摘 要

摘 要
实现通用处理器和操作系统自主可控是信息系统建设的基本要求和重要发
展方向。龙芯 2K1000 是具有完全自主知识产权的国产商用 MIPS 架构处理器，
可应用于移动智能终端、高端嵌入式应用、物联网等领域。Android 操作系统目
前被广泛应用于以手持移动智能终端为代表的各类终端硬件平台，其市场占有
率高达 73.3%，将 Android 操作系统移植到龙芯 2K 平台上，对于国产处理器平台
借助 Android 操作系统进一步拓展市场具有极其重要的意义。本文基于龙芯 2K
平台实现了 Android 5.1.1 操作系统的移植，并在此基础上进行了性能优化方法
研究。然后采用相关性能测试工具进行了全面的性能测试和分析，论证 Android
5.1.1 操作系统在龙芯 2K 平台上的可用性。
本文主要工作如下：
1. 基于龙芯 2K 平台的 Android 5.1.1 操作系统移植。本文以 Android 5.1.1 操
作系统能够在龙芯 2K 平台上正常运行与交互为目标，研究 Android 5.1.1 系统中
Linux 内核适配、Android 操作系统开发与编译环境搭建、Android 运行时（ART）
和 Android 图形子系统重构与移植等核心难点，使 Android 5.1.1 操作系统成功运
行在龙芯 2K 平台上。
2. 基于龙芯 2K 平台 Android 5.1.1 操作系统优化与性能分析。针对 Android
5.1.1 操作系统在龙芯 2K 平台下运行卡顿、界面不流畅的问题，本文利用性能分
析工具对影响系统使用的关键功能进行测试，定位并分析性能瓶颈，针对性能问
题进行优化。除此之外，本文实现龙芯 2K 平台图形硬件加速优化，使 Android
5.1.1 操作系统的 2D、3D 图形渲染能力相比于软件渲染模式有很大的提升。通
过上述优化，Android 5.1.1 操作系统可流畅运行于龙芯 2K 平台上。
本文使用谷歌官方提供的 Android 系统性能测试工具对运行在龙芯 2K 平台
下的 Android 5.1.1 操作系统性能进行了全面的测试及分析。通过与真实手机下
的测试结果对比，基于龙芯 2K 平台的 Android 5.1.1 操作系统已具备流畅运行的
能力，为龙芯 2K 平台开拓市场提供了有力的技术支持。

关键词：龙芯，安卓，系统移植，系统优化，性能分析

Abstract

Abstract
Realizing the independently controllable of general-purpose processors and operating systems is the basic requirement and important development direction of information
system construction. Loongson 2K1000 is a domestic commercial MIPS architecture
processor with completely independent intellectual property rights, which can be used
in mobile intelligent terminals, high-end embedded applications, Internet of Things and
other ﬁelds. The Android operating system is currently widely used in various terminal hardware platforms represented by smartphones, and its market share is as high as
73.3%. Porting the Android operating system to the Loongson 2K platform is extremely
important for the domestic processor platform to further expand the market with the help
of the Android operating system. This paper implements the transplantation of the Android 5.1.1 operating system based on the Loongson 2K platform, and on this basis, the
performance optimization method is studied. Then use the relevant performance testing tools to conduct a comprehensive performance test and analysis to demonstrate the
availability of the Android 5.1.1 operating system on the Loongson 2K platform.
The main work of this article is as follows:
1. Android 5.1.1 operating system transplantation based on the Loongson 2K platform. This article aims at the normal operation and interaction of the Android 5.1.1
operating system on the Loongson 2K platform. It studies the Linux kernel adaptation
in the Android 5.1.1 system, building the Android system development and compilation
environment, Android runtime (ART) and Android graphics subsystem reconstruction
and transplantation, and other core issues. The purpose is to make the Android 5.1.1
operating system successfully run on the Loongson 2K platform.
2. Based on Loongson 2K platform Android 5.1.1 operating system optimization
and performance analysis. In response to the problem of the Android 5.1.1 operating
system based on the Loongson 2K platform running stuck and the interface not smooth,
this article uses performance analysis tools to test the key functions that aﬀect the use of
the system, locate and analyze performance bottlenecks, and optimize for performance

problems. Besides, this paper realizes the optimization of graphics hardware acceleration of the Loongson 2K platform, so that the rendering capability of 2D and 3D graphics
in Android 5.1.1 operating system is greatly improved compared to the software rendering mode. Through the above optimization, the Android 5.1.1 operating system can run
smoothly on the Loongson 2K platform.
This article uses the Android system performance test tool oﬃcially provided by
Google to conduct a comprehensive test and analysis of the performance of the Android
5.1.1 operating system running on the Loongson 2K platform. By comparing with the
test results under real mobile phones, the Android 5.1.1 operating system based on the
Loongson 2K platform already has the ability to run smoothly, providing strong technical support for the Loongson 2K platform to develop the market.

研究背景与意义

1.1

研究背景

1.1.1

目前，全球出售的智能手机中 Android 操作系统占比达到 73.3% [1] 。Android
操作系统，最初是由 Android 公司（2005 年被 Google 公司收购）在基于 Linux 内
核的修改版以及其他开源软件的基础上构建的移动操作系统 [2] 。其早期版本由
以 Google 公司为首的数家软件开发商、手机制造商，以及电信运营商组成的开
[3]
放手持联盟（OHA）
发布。当前 Android 操作系统最新的稳定版本是 2019 年 9

月 3 日发布的 Android 10。Google 公司采取 Apache 免费开源许可证的授权方式
公开 Android 操作系统的核心源代码，并在此基础上通过创建 Android 开放源代
码项目（AOSP）来主导 Android 操作系统的持续开发与改进 [4] 。Android 操作系
统因其开源的特性获得了大量软硬件企业持续的资源投入，形成了一个良性循
环的软硬件生态圈。
Android 操作系统采用先进的层次化结构设计理念，大大简化了系统中不同
层级之间的耦合性。在此基础上，Android 操作系统选用具有平台无关特性的 Java
语言作为其应用程序开发语言，并且通过系统中的 Android 运行时（ART）环境、
Java 核心库，为每一个上层应用程序提供了独立的运行时环境，使得 Android 应
用程序具备了良好的安全性、跨平台性。
Linux 发行版操作系统运行于 x86、ARM 等硬件平台，Windows 操作系统运
行于 x86 平台，而 Android 作为一款基于 Linux 内核的移动操作系统，同样也需
要硬件平台来承载。目前市面上绝大多数使用 Android 操作系统的终端设备采用
ARM 处理器硬件方案。这是因为 ARM 架构作为 RISC 处理器的代表，其架构设
计与实现更加符合现代移动智能终端设备对于处理器高性能、低功耗的要求。众
多 ARM 硬件厂商对 Android 操作系统中的核心模块进行了持续深入的优化，这
也进一步促使适配 Android 操作系统的 ARM 消费类终端设备领域保持了极高的
市场占有率。
Android 操作系统并非只能运行在 ARM 平台上，上述 RISC 处理器中除
ARM 架构外，我国科研工作者研发的，具有完全自主知识产权的 MIPS 架构

在技术应用层面，AOSP 官方选择持续针对 ARM 架构处理器对 Android 操
作系统进行开发及演进。这也意味着 Android 操作系统在 MIPS 架构处理器上需
要做大量的移植与优化工作。将 Android 操作系统成功适配到国产龙芯处理器平

技术与操作系统技术共同发展进步。
在行业发展层面，我国正面临着异常严峻的国际环境，处理器与操作系统作
为核心技术的代表、互联网时代的基石，对于国家安全具有至关重要的意义。在
此背景下，我国科技工作者研发出了以龙芯系列处理器为代表的具有完全自主
知识产权的国产通用处理器。目前市场上除了高新技术的竞争之外，还面临着以
技术生态为壁垒的商业竞争。以传统个人计算机行业为例，以英特尔和微软为代
表的多家企业创立并主导了 Windows & Intel 体系封闭生态圈，并迅速占领全球
市场，该生态圈的核心资源不会对其他企业开放，形成商业壁垒。在此种行业背
景下，新兴企业要么游离于已被这种封闭生态圈占领的广袤的市场之外，难有参
与商业合作的机会；要么试图从零开始，打造一套由自己主导的生态壁垒，但是
由于基础差、起点低、创新不够等问题，难以真正发展自有生态。
相比之下，消费类终端行业所呈现的发展模式与个人计算机行业有较大不
同。因 Android 操作系统免费、开放的商业策略，Android 平台的硬件设备和应
用程序都保持迅猛的增长态势。使得 Android 系统吸引了整个产业链上下游的众
多合作者来共同创造和分享 Android 生态圈的巨大市场蛋糕。
龙芯 2K 平台面向消费者智能移动终端，积极融入 Android 生态圈，将 Android 操作系统移植到自身平台，进而推出相应的系统级方案，有利于龙芯利用
Android 生态圈的各种资源及用户群体来拓展目标市场，提升自身产品的竞争力。
因此，本文研究系统类移植的关键技术，实现了基于龙芯 2K 平台的 Android
5.1.1 操作系统的移植，并针对系统性能问题进行优化，为拓展龙芯生态圈提供
了支持，有着重要的研究意义。

第2章

Android 系统框架及相关技术研究

Android 系统框架及相关技术研究

本章将对 Android 5.1.1 的系统架构、关键子模块，以及与目标平台相关的模
块进行深入地分析研究，为后续的 Android 系统移植优化工作提供理论准备。
2.1

Android 系统框架
Android 操作系统专为消费类智能终端打造，这类设备普遍具有处理器性能

不高，内存较小，使用电池供电，需要低功耗运行的特点。针对这类硬件平台的特
点，Android 操作系统采用了精妙的层次化架构设计，将系统底层至顶层功能解
耦。Android 操作系统最底层采用定制化的 Linux 内核，通过硬件抽象层（HAL，
Hardware Abstraction Layer）向上提供各种设备驱动的接口，屏蔽了底层设备的实
现细节。Android 运行时环境及本地函数库向使用 Java 语言开发的 Android 应用
程序提供了统一的运行平台，同时经过应用框架层的支持，大大简化了 Android
应用程序的开发难度。综上，这种架构设计模式中每一层在对其上层提供统一服

Android 定制 Linux 内核关键驱动分析

2.2

Android 操作系统通过定制 Linux 内核，对上层系统提供了进程管理、内存

Android 系统核心库之间构建了第一层次的硬件抽象。
与其他 Linux 发行版操作系统不同，Android 操作系统摒弃了主流桌面 Linux
操作系统中使用的 glibc 本地共享库以及图形窗口系统，这使得传统桌面 Linux
系统中使用的应用程序不与 Android 系统兼容 [13] 。
Android 除了对 Linux 内核做大量剪裁定制外，还在 Linux 内核中添加了若
干新模块，以期通过优化 Linux 某方面的性能，使其能够适应基于移动处理器的
Android 操作系统应用场景。通过分析 Android 系统定制 Linux 内核，下文中总
结出了一些向 Android 上层系统提供关键功能的模块。
Binder 驱动

2.2.1

Linux 内核继承和兼容了丰富的 Unix 系统进程间通信（IPC）机制，传统的
进程间通信机制有管道（Pipe）、信号（Signal）和跟踪（Trace），这三项通信
手段只能用于父进程与子进程之间或者兄弟进程之间，后来又增加了命令管道
（Named Pipe），使得进程间通信不再局限于父子进程或者兄弟进程之间 [14] 。为
了更好地支持商业应用中的事务处理，在 AT&T 的 Unix 系统 V 中，又增加了三
种称为“System V IPC”的进程间通信机制，分别是报文队列（Message）
、共享内
存（Share Memory）和信号量（Semaphore）
，后来 BSD Unix 对“System V IPC”
机制进行了重要的扩充，提供了一种称为插口（Socket）的进程间通信机制 [15] 。
但是，在 Android 操作系统中并未采用以上进程间通信机制，而是另辟蹊径
采用了 Binder 进程间通信机制，该机制为运行在单机系统上的不同进程提供了
类似于分布式系统中远程过程调用（RPC）的功能 [16] 。
因为在 Android 系统中，Server 服务程序专门负责多媒体播放、视频音频信

协议实现 Client，并与 Server 进行进程通信就可以获取这些服务即可。目前 Linux
内核所支持的进程间通信机制并不适用于在系统资源量较紧张的消费类移动设
备上构建高效的 C/S（Client-Server）通信架构。因此，Android 操作系统使用了

Android 操作系统中进程的生命周期完全由系统进行管理，即使用户手动去

关闭一个应用，这个应用的进程上下文仍会在内存中存在一段时间。之所以这样

时释放内存的 Low Memory Killer 机制。
Linux 原有的 OOM 机制会在监测到系统可用内存不足时启动，通过一系列
较为复杂的评分算法对所有存在的进程进行打分，得分高者将被判定为 bad 进
程，进而被杀死以释放内存。而 Low memory killer 机制的启动机制为定时启动，
启动后 Low memory killer 会根据系统当前的剩余内存空间计算出一个警戒级数。

Android 运行时（ART）

2.4

Android 操作系统采用 Java 语言作为应用层和应用程序框架层的开发语言。
Java 源代码经 Java 编译器编译后，生成由字节码（Bytecode）组成的 class 文件。
Java 应用程序在目标平台上运行时，类加载器会将 class 文件加载到 Java 虚拟机
相应内存中，由虚拟机解释执行。由于单纯解释执行的运行方式效率较低，所以
目前主流的 Java 虚拟机，如 Hotspot、IBM JVM，除了含有最原始的解释执行模
块，还包含有支持在运行时将 Java 字节码编译为目标平台本地机器码的即时编
译模块（JIT）
，虚拟机在实际运行时会根据某些条件自行选择解释执行或编译执
行模式，采用 JIT 技术的 Java 编译器可较大幅度地提高 Java 应用程序整体的运
行效率。
Android 操作系统自始至终均未采用已有的 Java 虚拟机方案，Android 4.4
KitKat 及以前的 Android 版本针对手持移动设备 CPU 频率低、内存容量小以及
电池容量有限等特性专门开发了运用 JIT 技术的 Dalvik 虚拟机。随着各种复杂
Android 应用程序的推出，Dalvik 虚拟机 JIT 编译方式以及垃圾收集器的性能已
无法满足这些应用程序流畅运行的要求。另外，市场上高主频、多核心、支持 64
位应用移动处理器的出现，硬件算力得到大幅提升。面对这些现实情形，Android
操作系统于 Android 4.4 KitKat 版本引入 Android 运行时（ART）
，2014 年底发布
Android 5.0 Lollipop 版本后彻底抛弃 Dalvik 虚拟机。
使用 Dalvik 虚拟机的 Android 系统中，应用程序每次运行时都要通过即时编
译器将字节码转换为机器指令。而使用 ART 虚拟机的 Android 系统中，第一次
安装应用程序时就会使用提前编译技术（AOT）预先将字节码编译为机器指令，
使 Java 应用成为真正的本地应用。这样应用程序在安装时虽然会比 Dalvik 虚拟
机多花点时间，但是应用程序安装成功后，其启动和运行速度都会比使用 Dalvik
虚拟机的 Android 系统中的应用程序快。

相似，实则其背后机理迥然不同。使用 Dalvik 虚拟机的 Android 系统在安装应用
程序后使用 Java 语言开发的应用程序是以 dex 字节码的形式存在，应用程序在
每次执行时都需要将 dex 字节码解释为本地指令执行，只不过 Dalvik 虚拟采用
了 JIT 技术，程序运行后，随着时间的推移，越来越多的字节码被 JIT 编译器编
译成本地代码，从而获得一些执行效率。然而，当该应用结束本次运行，下次再
重新运行时又要重头开始，无法利用上次编译的本地代码。
使用 ART 虚拟机的 Android 系统由于采用的 AOT 技术，系统在安装 Android
应用程序时便通过得 dex2oat 工具将使用 Java 语言开发的 dex 字节码文件编译成
ELF 格式的 oat 本地代码文件，oat 文件格式如图 2.8所示。
应用程序安装完毕后，以后每次运行应用程序都无需解释执行 dex 字节码指

大大提升应用程序的运行效率。ART 虚拟机的优势便在于此。
总结 ART 运行时的运行原理如下。
1. Android 系统启动过程中创建 Zygote 进程利用 ART 运行时导出的虚拟机
接口创建 ART 虚拟机。
2. APK 安装时，将打包在 APK 中的 class.dex 文件使用 dex2oat 工具翻译成
本地机器指令，最终得到 ELF 格式的 oat 文件。
3. APK 运行时，将上述生成的 oat 文件加载到内存中，并且 ART 运行时通
过.oat 文件中的 oatdata 段和 oatexec 段，找到任意一个类方法对应的本地机器指
令执行。

运行时内存管理

2.4.2

ART 运行时相比于 Dalvik 虚拟机采取了更为高效和细粒度的内存管理，体
现在如下方面 [21] ：
2.4.2.1

内存分配器

Dalvik 虚拟机直接使用 Android 系统 C 语言库 bionic 中的 DlMalloc 开源内
存分配器，而 ART 运行时创建了一种名叫 Runs-of-Slots-Allocator（RosAlloc）的
内存分配器。此分配器分配内存时采用了更细粒度的锁控制，使用不同的锁保
护不同的分配对象。据 Google 介绍，这一内存分配器将带来接近 10 倍的速度提
升 [22] 。
2.4.2.2

垃圾回收算法优化

Dalvik 虚拟机的垃圾回收分为两个阶段：
• Dalvik 暂停所有线程来分析堆使用情况，标记垃圾对象。
• Dalvik 暂停所有线程清理堆，这就是导致应用出现“卡顿”的原因之一。
ART 运行时改进了垃圾回收算法，做到了只暂停一次，且暂停时间也有较
大幅度的缩短。
2.4.2.3

超大对象存储空间支持

ART 运行时引用了超大对象存储空间（LOS），这个空间与堆分开存在，但
仍驻留在应用程序内存空间中，添加 LOS 支持是为了更好的管理较大的对象，
因为堆空间碎片化较为严重时，会对较大的对象带来问题，从而增加垃圾收集器
的启动次数，若较大的对象与其他对象分开进行内存管理，则会大大减轻垃圾收
集器的工作压力。
2.4.2.4

Moving GC 策略

ART 运行时为了解决堆空间内存碎片化问题，专门引入了“Moving GC”方
法。其目的是减少内存碎片。但是这个工作会导致应用程序出现长时间的中断，
所以这个工作只能在应用程序退到后台时进行，其核心思想就是当应用程序在
后台时，将此程序的堆空间中的段做合并操作。

Java 语言开发，所以一般也将这三层统称为 Java 层。上文已经介绍，虽然在 Java
层中的程序会通过虚拟机的 JNI 机制调用在 C/C++ 层中实现的本地方法，其中
某些本地方法具有平台相关性；但由于 Java 语言本身具有完全的跨平台性，因
此在移植时只需要重新编译部署即可，无需对使用 Java 实现的源码进行修改。

因此，本课题通过 Docker 容器构建 Android 操作系统源码开发编译环境。
Docker 是一组平台即服务（PaaS）产品，它们使用操作系统级虚拟化以称为容器

具体做法是根据 AOSP 官网搭建 Android 操作系统源码开发编译环境的要

构建难度大、不灵活的问题，有效加快了课题推进速度。

另外，需要注意 Java 字节码编译成机器码后并不能像 C/C++ 源码编译成机
器码一样直接在 OS 上运行，Java 字节码编译为目标平台机器码的过程中，虚拟
机会添加一些必要和特殊的指令。这样，Java 机器码通过目标平台编译器后端编
译得到的机器码在运行过程中会时刻在虚拟机的管控之中。
举例来说，Java 虚拟机的垃圾回收器做对象标记前，一般会设置一个标志，
标识自己准备做对象标记。其他线程运行过程中会经常去检查这个标志，如果
发现此标志位 True 时，这些线程就得等待垃圾回收器做对象标记。否则，在垃
圾回收器做对象标记的过程中其他线程又去创建对象或更改对象间的引用关系，
这将会导致对象标记不准确，影响垃圾回收。
这个过程中，应用程序开发人员显然不会主动添加这个检查标记的操作。因

Android 5.1.1 图形子系统重构
Android 系统如果单纯使用通用处理器负责系统全部 2D/3D 图形的计算、渲

Android 设备均配置了硬件图形处理单元（GPU）来处理操作系统中图形子系统
的计算任务。龙芯 2K1000 也集成了 GPU，支持 OpenGL ES 2.0、OpenGL ES 1.1
图形程序接口。
Android 图形子系统中，Surfaceﬂinger 服务向应用程序提供绘图流的合成、图
形渲染、缓存管理等服务，而这些服务的实现则需要调用 Android 本地共享库中
提供的 OpenGL 接口和 EGL 接口 [33] 。Android 图形子系统架构如图 3.9所示 [34] 。
该子系统可由纯软件模拟实现，进行适当配置后编译出 libGLES_android.so 动态

通用性。但是，经测试发现将 Android 系统成功移植至龙芯 2K 平台后，使用纯
软件渲染的图形子系统虽然可以使系统正常工作，但其性能无法满足系统流畅
运行的要求，图形界面会频繁出现用户无法忍受的卡顿感。

图形子系统下启用图形硬件加速。但是，Mesa 3D 图形库 [35] 已经移植到龙芯

复杂度）和代码优化（提高执行速度、减少内存占用）。还可以评估程序对硬件
资源的使用情况，例如各级 cache 的访问次数，各级 cache 的丢失次数、流水线
停顿周期、前端总线访问次数等。也可以评估程序对操作系统资源的使用情况，
系统调用次数、上下文切换次数、任务迁移次数等 [41] 。Android 5.1.1 Lollipop 操
作系统源码包含 perf 工具，在“external/linux-tools-perf”目录下，因此本文可以
方便的使用 perf 工具分析相关热点函数，完成相关优化工作。

的性能瓶颈，并对相关内存操作函数进行了普通汇编优化。接着使用 0xbenchmark
性能测试工具对龙芯 2K 平台上的 Android 5.1.1 操作系统进行了算术运算性能、
2D、3D 图形渲染功能的性能测试，测试结果表明移植后的 Android 系统初步具
备了一定的实用性。
